# 聊天图片上传与 content_blocks 贯通

## 现状要点

- 流式发送在 [`frontend/src/hooks/chat.ts`](frontend/src/hooks/chat.ts) 中把 `content` 包装成单个 `TextBlock` 的 `contentBlocks`（约 221–232 行）；需改为合并「可选文本 + 若干图片块」。
- 后端 [`backend/app/schemas/chat.py`](backend/app/schemas/chat.py) 的 `ContentBlock` 目前为 `TextBlock | ThinkingBlock | ToolUseBlock | ToolResultBlock`，需加入 `ImageBlock`；`extract_user_text` 仅拼接 `TextBlock`，**无需改 LLM 管线**即可满足「暂不修改后端 llm 生成逻辑」。
- 用户气泡 [`frontend/src/pages/ChatPage/components/ChatMessage/UserMessage/index.tsx`](frontend/src/pages/ChatPage/components/ChatMessage/UserMessage/index.tsx) 仅用 `getMessageTextFromBlocks`，需增加对 `ImageBlock` 的展示（按 `contentBlocks` 顺序渲染文本与图片）。
- 助手侧 [`frontend/src/pages/ChatPage/components/ChatMessage/AssistantMessage/ContentBlocksRender/viewModel.ts`](frontend/src/pages/ChatPage/components/ChatMessage/AssistantMessage/ContentBlocksRender/viewModel.ts) 中 `isRenderableBlock` 当前把非 `tool_result` 都当可渲染，若把 `ImageBlock` 并入 `ContentBlock` 且不加分支，会误入 tool 分支；应在该处 **显式排除 `image` 类型**（助手消息预期不会出现用户图，仅作防御）。

## ImageBlock 约定（前后端一致）

建议字段（与现有 snake_case/camelCase 转换兼容）：

- `id: string`
- `type: "image"`
- `url: string` — 浏览器可直接作为 `<img src>` 使用的路径；与现有 `apiClient` 一致，使用 **以 `/api` 为前缀的站内路径**（如 `/api/file/...`），开发环境走 Vite 代理。

上传接口在成功响应的 `data` 中返回完整 `ImageBlock`（含可预览的 `url`）。

## 后端

1. **Schema**（[`backend/app/schemas/chat.py`](backend/app/schemas/chat.py)）
   - 新增 `ImageBlock`（`type: Literal["image"]`，`url` 必填）。
   - 更新 `ContentBlock` TypeAlias 与 `_CONTENT_BLOCKS_ADAPTER`（Discriminated union 会随 `Literal["image"]` 自动识别）。
   - 文件末尾 `model_rebuild()` 已存在，补全后确认无循环引用。

2. **存储路径**
   - 目录：`data/user_data/{user_id}/uploads/`（启动或首次写入时 `mkdir(parents=True)`）。
   - 文件名：建议使用 `uuid` + 从原始文件名推断的安全扩展名（如 `.png`、`.jpg`），避免路径穿越。

3. **API**（在 [`backend/app/api/file.py`](backend/app/api/file.py) 内**直接扩展**：新增路由函数；落盘与校验等可抽成 `app/services/...` 中的函数再由 `file.py` 调用，但**路由注册与对外路径仍只通过该文件**，[`backend/app/main.py`](backend/app/main.py) 无需新增 router。）
   - **POST** `/api/file/.../upload`（名称自定，如 `upload_chat_image`）：`UploadFile`，`Depends(require_auth)` 或等价的 `get_auth_token_info` 取 `user_id`；校验 MIME（如 `image/jpeg`、`image/png`、`image/gif`、`image/webp`）与大小上限；保存文件；返回 `ApiResponse[ImageBlock]`，`url` 指向下方预览路径（建议包含 `user_id` 与 `filename` 两段，便于 O(1) 定位文件）。
   - **GET** `/api/file/.../preview/{user_id}/{filename}`：**不挂载登录依赖**；解析路径，严格校验 `filename` 仅含安全字符；拼接为 `data/user_data/{user_id}/uploads/{filename}`，存在则 `FileResponse`，否则 404。禁止 `..` 与越界。

4. **业务影响**
   - 消息落库已使用 `block.model_dump(mode="json")`，`ImageBlock` 会随用户消息 JSON 持久化。
   - `format_chat_message_for_llm` / `extract_user_text` 仍只基于文本，图片不会进入多模态模型（符合当前「不改 LLM」范围）。

## 前端

1. **类型**（[`frontend/src/interfaces/contentBlock.ts`](frontend/src/interfaces/contentBlock.ts)、[`frontend/src/interfaces/chat.ts`](frontend/src/interfaces/chat.ts)）
   - 定义 `ImageBlock`；`ContentBlock` 联合类型加入 `ImageBlock`；`UserContentBlock` 改为 `TextBlock | ImageBlock`。
   - **`ChatInputFormValues` 不单独增加 `imageBlocks` 字段**：图片以 `@ant-design/x` 的 `Attachments` 的 `items`（`UploadFile[]`）为唯一数据源；上传成功后把服务端返回的 `ImageBlock` 存到对应 `UploadFile` 的扩展字段（如 Ant Design Upload 的 `response` / 自定义 `xhr` 结果，或项目约定的 `xxx` 字段），**发送前**由 `items` 映射/过滤出 `ImageBlock[]`（仅 `status === 'done'` 且已拿到块结构）。若需在类型上表达「发送入参」，可在 `sendMessage` 侧使用独立参数或局部类型，而不必塞进 Form 的 values。

2. **上传 API**（[`frontend/src/services/file.ts`](frontend/src/services/file.ts)）
   - `uploadChatImage(file: File): Promise<ImageBlock>`，`FormData` + 现有 `apiClient`（与头像上传类似）。

3. **ChatInput**（[`frontend/src/pages/ChatPage/components/ChatInput/index.tsx`](frontend/src/pages/ChatPage/components/ChatInput/index.tsx)）
   - 参考你提供的 `Sender` + `Sender.Header` + `Attachments` 示例：回形针打开附件区；`beforeUpload` 返回 `false` 避免默认上传，在 `customRequest` 或 `onChange` 中调用 `fileAPI.uploadChatImage`，成功后把返回的 `ImageBlock` **写回当前 `UploadFile` 项**（见上节），由 `items` 驱动列表与缩略图（缩略图可用 `ImageBlock.url` 或 `thumbUrl`）。
   - `onPasteFile` 中触发上传并展开附件区。
   - **发送条件**：`trim(text)` 非空 **或** `items` 中至少一项已上传完成且可映射为 `ImageBlock`；对应调整 [`hooks.ts`](frontend/src/pages/ChatPage/components/ChatInput/hooks.ts) 的 `useButtonState` 与 [`util.ts`](frontend/src/pages/ChatPage/components/ChatInput/util.ts) 的禁用逻辑（需能感知附件 `items` 或等价计数，而非仅 `content` 字符串）。
   - 发送成功后清空文本与 **`Attachments` 的 `items`**（与示例 `onSubmit` 行为一致）。

4. **sendMessage**（[`frontend/src/hooks/chat.ts`](frontend/src/hooks/chat.ts)）
   - 组装 `contentBlocks`：**顺序建议为** 先 `TextBlock`（若有非空文本），再按 **`Attachments` items 顺序**追加 `ImageBlock`（若产品要求「图在文前」可再改，实现上仅调整 push 顺序）。
   - 若两者皆空则直接 return（不发起请求）。
   - **重发** `reSendMessage`：无 Attachments 上下文，从该条用户消息的 `contentBlocks` 中过滤出 `ImageBlock`，与文本一并作为参数传给 `sendMessage`（与「由 items 派生」并列的入参形状，可用重载或可选字段 `contentBlocks?: UserContentBlock[]` 仅用于重发/程序化调用）。

5. **展示**
   - [`UserMessage/index.tsx`](frontend/src/pages/ChatPage/components/ChatMessage/UserMessage/index.tsx)：按 `contentBlocks` 顺序渲染：文本块合并展示（保持现有复制/编辑行为可仍以纯文本为主；编辑模式可仅编辑文本，图片编辑可作为后续增强），图片块用 `<img alt="" />` 或 antd `Image` 预览。
   - [`viewModel.ts`](frontend/src/pages/ChatPage/components/ChatMessage/AssistantMessage/ContentBlocksRender/viewModel.ts)：`isRenderableBlock` 对 `type === "image"` 返回 `false`，避免误入 tool 渲染逻辑。

6. **其它**
   - 全局搜索 `UserContentBlock` / `ContentBlock` 的 switch，按项目 [typescript-exhaustive-switch](file:///Users/apple/.cursor/plugins/cache/cursor-public/cursor-team-kit/08c2bbe2ae8a022a21dc6c32faf611f14a6e8343/rules/typescript-exhaustive-switch.mdc) 规则补全 `image` 分支或收窄类型。

```mermaid
  UI->>API: POST multipart image
  API->>BE: auth upload
  BE->>Disk: save file
  BE-->>API: ImageBlock url
  UI->>UI: items 项挂载 ImageBlock，发送时由 items 派生
  UI->>BE: POST chat stream JSON content_blocks
  Note over BE: extract_user_text 仅文本; LLM 不变
```
