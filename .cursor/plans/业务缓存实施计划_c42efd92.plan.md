# 业务缓存实施计划

## 1. 缓存基础设施与依赖

- 新增 [`backend/app/core/local_cache.py`](backend/app/core/local_cache.py)：用带锁的 `cachetools.TTLCache` 实现进程内 L1，固定用于 `models/global`（300s）和 `health/redis_ping`（5s）。单独拆出该模块，避免 `config -> cache -> redis -> config` 循环导入。
- 新增 [`backend/app/core/cache.py`](backend/app/core/cache.py)：实现异步 L2 JSON get/set、512 KiB 上限、`SCAN + UNLINK` 批量删除、标准 key 构造、owner envelope 解析，以及 `invalidate_user` / `invalidate_conversation` / `invalidate_messages` / 组合失效函数。
- 命中/未命中用 debug 日志，失效/超限用 info，Redis 操作异常用 error 后继续抛出；本期保持 fail-closed。
- 在 [`backend/pyproject.toml`](backend/pyproject.toml) 增加 `cachetools>=5.3.0`，通过 `uv` 同步 [`backend/uv.lock`](backend/uv.lock)。

## 2. 六个读接口接入

- [`backend/app/api/models.py`](backend/app/api/models.py)：模型响应使用 L1；[`backend/app/core/config.py`](backend/app/core/config.py) 在 settings reload 后通过独立 L1 模块清理 `models` namespace。
- [`backend/app/api/health.py`](backend/app/api/health.py)：缓存 Redis 状态 5 秒，避免每请求 PING。
- [`backend/app/services/user/user_db.py`](backend/app/services/user/user_db.py) + [`backend/app/api/user.py`](backend/app/api/user.py)：新增异步 get-or-load，L2 命中后恢复为 `UserDb`，未命中查 DB 并回填。
- [`backend/app/services/conversation/conversation_db.py`](backend/app/services/conversation/conversation_db.py) + [`backend/app/api/conversation.py`](backend/app/api/conversation.py)：接入 detail（30s）、list（10s、空 cursor 规范化）、messages（15s、512 KiB 上限）。detail/messages 缓存使用 `{owner_user_id, response}` envelope。
- detail/messages handler 改用 `get_auth_token_info`；命中校验 envelope owner，未命中校验 DB owner，归属不符统一按 404 处理，避免泄露资源存在性。

## 3. 写路径与提交后失效

保留底层同步 SQLModel 方法，在 service/API/orchestrator 的异步业务边界执行“写入 → 明确 `commit()` 成功 → `await invalidate_*`”，禁止在 commit 前删缓存：

- [`backend/app/services/conversation/conversation_db.py`](backend/app/services/conversation/conversation_db.py)、[`backend/app/api/conversation.py`](backend/app/api/conversation.py)：register 清 list；update/activate 清 detail+list；delete 清 detail+list+messages。同步补齐 update/delete ownership。
- [`backend/app/api/chat.py`](backend/app/api/chat.py)：非幂等新 turn 创建并提交后清 messages+detail+list；幂等命中不重复失效；stop fallback 在 DB context 提交后清三类缓存。
- [`backend/app/services/chat/chat_orchestrator.py`](backend/app/services/chat/chat_orchestrator.py)：DONE、STOPPED、FAILED 每次消息状态提交后清 messages+detail+list；正常完成继续复用 [`backend/app/services/chat/post_process_service.py`](backend/app/services/chat/post_process_service.py) 的持久化结果。
- [`backend/app/services/message/message_db.py`](backend/app/services/message/message_db.py)、[`backend/app/api/message.py`](backend/app/api/message.py)：删除消息提交后清 messages；feedback 提交后清 messages+detail+list；补齐消息归属校验。
- [`backend/app/services/user/user_db.py`](backend/app/services/user/user_db.py)、[`backend/app/api/user.py`](backend/app/api/user.py)、[`backend/app/api/auth.py`](backend/app/api/auth.py)、[`backend/app/services/auth/sms_service.py`](backend/app/services/auth/sms_service.py)：用户资料更新、短信/微信登录资料更新、登出状态更新提交后清 user detail。

## 4. 测试覆盖

- 新增 [`backend/tests/core/test_cache.py`](backend/tests/core/test_cache.py)：L1 namespace/TTL/清除，L2 hit/miss/序列化/错误日志，512 KiB 跳过，cursor key，`SCAN + UNLINK`。
- 新增 user/conversation 缓存 service 测试：miss→DB→回填、hit 跳过 DB、类型恢复、分页 key、owner envelope 拒绝越权、404 不缓存。
- 扩展 conversation/message/chat 测试：逐项断言 commit 发生在失效之前；覆盖 register/update/activate/delete、feedback/delete、turn 创建、DONE/STOPPED/FAILED、stop 双路径、幂等重放不失效。
- 扩展 [`backend/tests/mcp/test_reload.py`](backend/tests/mcp/test_reload.py) 或新增 config 测试，验证 settings reload 会清 models L1。

## 5. 验证与边界

- 运行 `cd backend && uv sync --extra dev --group dev`、缓存相关 pytest、`make lint`、`make check`，再运行 `make test -- --ignore=tests/mcp_demo`（若 Makefile 不透传参数则直接使用对应 `uv run pytest`）。
- 无数据库模型/schema 变更，不创建 Alembic migration；保留当前工作区已有 model/doc/plan 修改，不覆盖或回退。
- 本期明确不做：TTL 抖动、负缓存、Redis fail-open、single-flight/分布式锁、chat history/context/memory 内部缓存。
