# process_history_messages 改造计划

## 目标
把历史消息处理拆成“预处理”和“组装”两个阶段，形成更清晰的职责边界：
- [`/Users/apple/Desktop/code/chat-agent/backend/app/services/chat/history_context_service.py`] 负责窗口裁剪、窗口外摘要，以及窗口内历史消息的预处理。
- [`/Users/apple/Desktop/code/chat-agent/backend/app/agents/base.py`] 的 `_compose_messages()` 只负责将已经预处理好的 `history_messages` 转成最终发给 LLM 的历史消息。
- 工具结果仍按现有长度策略压缩，但直接回写到原 `ToolResult` 的 `content`，并清空 `summary`；不再把工具结果二次拼接到 user message。

## 实施步骤
1. 在 [`/Users/apple/Desktop/code/chat-agent/backend/app/services/chat/history_context_service.py`] 缩减 `HistoryContextService` 职责。
移除 `prepare_history_messages()` 对 `process_history_messages()` 的调用，让它只返回窗口内原始历史；保留 `split_history_by_rounds_and_tokens()` 和窗口外摘要持久化逻辑不变。

2. 保留历史消息预处理在 [`/Users/apple/Desktop/code/chat-agent/backend/app/services/chat/history_context_service.py`]，但收敛其职责。
让预处理只做两类事情：识别 `assistant` 消息中的 `tool_use` / `tool_result` 块，并对 `ToolResult` 执行内容回写与 `summary` 清理；不再承担把工具结果拼进 user message 的职责。

3. 调整工具结果筛选规则。
不再使用当前“仅保留成功且成对工具调用”的语义作为入口条件；改为对历史中的所有 `ToolResult` 统一处理，不区分 `is_error`。如仍需保留 `ToolUse` 与 `ToolResult` 的配对顺序，则仅做结构遍历，不以 `is_error` 作为过滤条件。

4. 保留现有长度压缩策略，但压缩发生在历史预处理阶段，而不是 `_compose_messages()` 中。
沿用当前规则：最近一轮工具结果保留原文，旧轮次优先使用 `summary`，否则按 `message_summary_threshold_tokens` 截断 `content`。区别在于：
- 结果直接写回原 `ToolResultBlock.content`
- 同时将 `ToolResultBlock.summary` 置空或移除
- 不再生成 `tool_items`，也不再调用 `get_user_message_combine_tool_calls()` / `replace_text_content_blocks()`

5. 调整 `_compose_messages()` 的输入约定，而不是给它增加压缩职责。
[`/Users/apple/Desktop/code/chat-agent/backend/app/agents/chat_session_agent.py`] 继续把 history 传给 `_compose_messages()`，但传入的应是“已经完成 tool result 预处理”的历史消息；因此重点是梳理 [`/Users/apple/Desktop/code/chat-agent/backend/app/services/chat/chat_orchestrator.py`] 到 [`/Users/apple/Desktop/code/chat-agent/backend/app/agents/chat_session_agent.py`] 之间的调用约定，确认 `_compose_messages()` 只做格式组装，不持有 token 阈值或压缩配置。

6. 清理废弃逻辑与引用。
删除或降级 `process_history_messages()` 及其仅为“拼 user_message”服务的依赖调用，重点检查 [`/Users/apple/Desktop/code/chat-agent/backend/app/services/chat/history_context_service.py`] 中对 `filter_tool_call_messages`、`format_tool_call_messages_for_llm`、`get_user_message_combine_tool_calls`、`replace_text_content_blocks`、`collect_text_from_blocks` 的引用是否还需要保留。

## 验证点
- 窗口外摘要逻辑仍只受 `prepare_history_messages()` 控制，返回值结构不变。
- 历史中的失败 `tool_result` 会出现在发给 LLM 的 history 中，不再被成功过滤规则丢弃。
- 历史 user 消息文本保持原样，不再包含“请基于以上信息回答以下用户问题”这类拼接内容。
- 旧轮次 `ToolResult` 的 `content` 被压缩/替换后，`summary` 已清空；最近一轮保留原始 `content`。
- `_compose_messages()` 不负责压缩，只消费已预处理的 history；`ChatSessionAgent.stream_execute()` 组装出的 `messages` 顺序仍是 `system -> history -> user -> runtime tool_call_messages`。
