# 上下文压缩方案设计

## 问题分析

当前聊天服务存在上下文超长问题，主要由MCP工具调用返回大量数据导致：

1. **tavily_extract工具**：URL内容提取可能返回200KB+数据
2. **tavily_search工具**：关键词搜索可能返回20KB+数据
3. **上下文累积**：工具调用结果直接传递给响应生成Agent，超出模型上下文窗口限制

## 方案设计

### 阶段1：解决单轮问答上下文超长问题

#### 1.1 工具结果预处理层

**位置**：在`MCPToolsAgent`和`ResponseGenerationAgent`之间添加预处理层

**核心思路**：
- 对每个工具调用结果进行智能压缩
- 保留关键信息，过滤冗余内容
- 基于内容类型采用不同压缩策略

**压缩规则**：
- **内容识别**：自动识别内容类型（网页、搜索结果、API响应等）
- **保留优先级**：标题、核心段落、结构化数据、关键事实
- **过滤规则**：导航栏、广告、版权信息、重复内容、无关链接

## 实施方案

### 3.1 架构修改

**新增组件**：
```
ChatService
├── ContextCompressionService    # 新增：上下文压缩服务
│   ├── ToolResultCompressor     # 工具结果压缩器

│   └── ConversationManager     # 会话上下文管理器
├── MCPToolsAgent
├── ComponentToolsAgent
└── ResponseGenerationAgent
```

### 3.2 实施步骤

#### 阶段1实施（单轮压缩）：
1. 创建`ContextCompressionService`类
2. 实现各类型工具结果的压缩器
3. 在`ChatService.stream_message`中集成压缩逻辑
4. 添加监控和日志

#### 阶段2实施（多轮压缩）：
1. 扩展`ContextCompressionService`支持多轮管理
2. 实现历史上下文压缩策略
3. 添加会话状态持久化
4. 优化相关性算法

## 预期效果

### 性能提升
- **上下文长度**：减少70-80%的冗余内容
- **响应速度**：压缩处理耗时<100ms
- **成功率**：避免90%的上下文超限错误

### 信息保留
- **关键信息**：保留率>90%
- **用户体验**：压缩内容仍能支持准确回答
- **可追溯性**：保留原始数据的引用链接

## 监控和优化

### 4.1 指标监控
- 压缩前后内容长度对比
- 信息保留率统计
- 处理耗时监控
- 压缩失败率

### 4.2 动态调整
- 基于使用情况动态调整压缩阈值
- A/B测试不同压缩策略效果
- 用户反馈收集和算法优化

## 风险控制

### 5.1 降级策略
- 压缩失败时使用原始内容（带长度限制）
- 单轮压缩失败时跳过该工具结果
- 多轮压缩失败时只保留最近1轮

### 5.2 数据安全
- 敏感信息过滤
- 压缩过程不存储中间结果
- 失败时不暴露原始数据

## 总结

该方案通过分阶段实施，系统性地解决了MCP工具调用结果过长的问题：

1. **阶段1**：解决单轮问答中的上下文超长问题，通过智能压缩单个工具结果
2. **阶段2**：解决多轮对话中的上下文累积问题，通过历史上下文管理和相关性过滤

方案设计注重实用性，既保证信息保留率，又确保系统稳定性，为后续优化奠定基础。
