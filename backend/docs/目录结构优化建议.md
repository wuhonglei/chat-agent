# App 目录结构优化建议

## 当前结构分析

### ✅ 优点
1. **分层清晰**：API、Service、Model 三层分离
2. **核心配置集中**：`core/` 目录管理配置和数据库
3. **工具函数独立**：`utils/` 统一管理工具函数
4. **中间件独立**：`middleware/` 职责明确

### ⚠️ 问题与建议

#### 1. Models 目录职责混乱 ⭐⭐⭐ (高优先级)

**当前问题：**
- `models/` 目录混合了数据库模型（SQLModel）和 Pydantic 请求/响应模型
- 文件命名不够清晰，难以区分模型类型

**建议优化：**
```
app/
├── models/          # 数据库模型（SQLModel）
│   ├── __init__.py
│   └── db.py            # UserDb, ConversationDb, MessageDb
│
└── schemas/             # Pydantic 模型（请求/响应）
    ├── __init__.py
    ├── auth.py
    ├── chat.py
    ├── conversation.py
    ├── user.py
    ├── response.py
    ├── token.py
    └── ...
```

**优势：**
- 职责清晰：数据库模型和 API 模型分离
- 易于维护：修改 API 模型不影响数据库模型
- 符合 FastAPI 最佳实践

#### 2. API 层与 Service 层使用不一致 ⭐⭐ (中优先级)

**当前问题：**
- `api/conversation.py` 直接操作数据库
- `api/user.py` 使用 service 层
- 代码风格不统一

**建议优化：**
- 所有 API 路由都应该通过 Service 层处理业务逻辑
- API 层只负责：
  - 参数验证
  - 调用 Service
  - 返回响应

**示例：**
```python
# ❌ 不推荐：API 层直接操作数据库
@router.get("/list")
async def get_conversations(db: Session = Depends(get_db), ...):
    conversations = db.exec(select(ConversationDb)...).all()
    # ...

# ✅ 推荐：通过 Service 层
@router.get("/list")
async def get_conversations(
    db: Session = Depends(get_db),
    token_info: SecretTokenInfo = Depends(get_auth_token_info),
):
    service = ConversationService(db)
    conversations = service.get_conversations(token_info.user_id)
    return ApiResponse.success(data=conversations)
```

#### 3. JWT 目录可合并 ⭐ (低优先级)

**当前问题：**
- `jwt/` 目录只有一个文件 `jwt_manager.py`
- 可以合并到 `core/`

**建议优化：**
```
# 方案1：合并到 core/
app/core/
├── config.py
├── db.py
└── jwt.py          # 从 jwt/jwt_manager.py 移过来
```

**推荐方案1**：JWT 管理属于核心功能，放在 `core/` 更合适

#### 4. MCP 目录结构合理 ✅

**当前状态：**
- `mcp/` 目录结构清晰，按功能模块组织
- 每个 MCP server 都有独立的目录
- 保持现状即可

## 迁移步骤

### 阶段1：拆分 Models 和 Schemas（高优先级）

1. 创建 `schemas/` 目录
2. 将 Pydantic 模型从 `models/` 移动到 `schemas/`
3. 保留 `models/db.py` 作为数据库模型
4. 更新所有导入语句

### 阶段2：统一 API 层使用 Service（中优先级）

1. 创建 `ConversationService`（如果不存在）
2. 重构 `api/conversation.py` 使用 Service 层
3. 确保所有 API 路由都通过 Service 层

### 阶段3：合并 JWT 目录（低优先级）

1. 将 `jwt/jwt_manager.py` 移动到 `core/jwt.py`
2. 更新导入语句
3. 删除 `jwt/` 目录

## 总结

当前目录结构整体良好，主要优化点：
1. ⭐⭐⭐ **拆分 Models 和 Schemas** - 提高代码可维护性
2. ⭐⭐ **统一 API 层使用 Service** - 保持代码风格一致
3. ⭐ **合并 JWT 目录** - 简化目录结构

这些优化可以逐步进行，不影响现有功能。
