# 用户与认证模块说明（当前实现）

> 状态：现网实现。本文档以 `app/api/auth.py`、`app/api/user.py`、`app/core/jwt.py` 为准。

## 1. 认证接口（`/api/auth`）

- `POST /api/auth/sms/send`：发送短信验证码
- `POST /api/auth/sms/login`：短信验证码登录
- `POST /api/auth/wechat/init`：微信登录初始化
- `POST /api/auth/wechat/login`：微信登录回调登录
- `POST /api/auth/logout`：退出登录

说明：

- 登录成功后，服务端会在响应头写入 `x-secret-token-info`；
- 该 token 用于后续业务接口的 `Authorization: Bearer <token>` 鉴权；
- 短信验证码由后端生成并保存在 Redis，验证码有效期为 300 秒。

### 1.1 短信验证码登录约束

`POST /api/auth/sms/send` 成功时返回：

```json
{
  "verification_id": "uuid",
  "expires_in": 300,
  "phone_number": "13800138000"
}
```

关键行为：

- Redis key 格式为 `sms:verify:{verification_id}`，内容包含验证码和手机号；
- 发送短信前先写 Redis，腾讯云短信发送失败时会回滚删除该 key；
- `POST /api/auth/sms/login` 使用 `verification_id` + `verification_code` + `phone_number` 校验；
- 校验成功后删除验证码并按手机号创建或更新用户，JWT 载荷中的 `last_login_type` 为 `sms`；
- 验证码错误或手机号不匹配返回 `400`，验证码保留到 TTL 过期，允许用户重试；
- Redis 读写失败返回 `503`：`验证码服务暂不可用`。

运维检查：

- 应用启动时必须能连通 Redis，否则启动失败；
- `/api/health` 的 `redis` 字段返回 `ok` 或 `unavailable`；
- 本地环境可用 `REDIS__HOST`、`REDIS__PORT`、`REDIS__USERNAME`、`REDIS__PASSWORD` 覆盖 Redis 配置。

## 2. 用户接口（`/api/user`）

- `GET /api/user/detail`：获取当前用户信息
- `PUT /api/user/update_info`：更新用户资料
- `GET /api/user/memories`：获取用户记忆列表
- `DELETE /api/user/memories/{memory_id}`：删除单条记忆

补充：

- 头像上传：`POST /api/avatars/upload`；读取：`GET /api/avatars/{filename}`。

## 2.1 Mem0 用户记忆（聊天链路）

实现：`app/services/user/memory_service.py`，配置根为 `settings.chat_context.memory_config`（`MemoryConfig`）。

启用条件：`base_url` 与 `api_key` **均非空**；否则所有 HTTP 调用直接 no-op / 返回空列表。

请求头同时携带：

- `X-API-Key: {api_key}`
- `Authorization: Token {api_key}`

### 2.1.1 商业版 Platform 与自建 OSS 分流

`MemoryService._is_platform()` 在以下任一条件成立时走 Platform：

- host 为 `api.mem0.ai`（`https://api.mem0.ai` 或 `https://api.mem0.ai/v3` 均可）
- `base_url` 的 path 以 `/v3` 结尾（用于自建但挂了 v3 前缀的网关）

其余地址按自建 OSS 路径调用。Platform 路径**必须带尾斜杠**（Django 否则 301，httpx 默认不跟随 POST 重定向）。

| 能力 | Platform | 自建 OSS | 调用方 |
|------|----------|----------|--------|
| 写入 | `POST {origin}/v3/memories/add/` | `POST {base}/memories` | 对话后处理（fire-and-forget） |
| 搜索 | `POST {origin}/v3/memories/search/` | `POST {base}/search` | `ChatService._search_user_memories` |
| 列表 | `POST {origin}/v3/memories/?page=&page_size=`，body `{"filters":{"user_id"}}` | `GET {base}/memories?user_id=` | `GET /api/user/memories` |
| 删除单条 | `DELETE {origin}/v1/memories/{id}/` | `DELETE {base}/memories/{id}` | `DELETE /api/user/memories/{memory_id}` |
| 删除全部 | `DELETE {origin}/v1/memories/?user_id=` | `DELETE {base}/memories?user_id=` | `MemoryService.delete_all_memories`（现网无对应 HTTP 路由） |

约束：

- Platform 列表按 `page_size=100` 分页，最多 20 页（约 2000 条）；响应 `next` 为空即停。
- Platform 的 `{origin}` 只取 scheme + host，忽略 `base_url` 上多余 path（`/v3` 不会叠进 URL）。
- 自建 OSS 的 `base_url` **不要**误加 `/v3` 后缀，否则会被判成 Platform 并打商业版路径。
- 写入 / 搜索 body 两边相同：`messages` + `user_id`（可选 `run_id` / `metadata`）；搜索为 `query` + `filters.user_id` + `top_k` + 可选 `threshold`。
- 解析同时兼容裸数组与 `{results:[...]}` envelope。

默认配置（可用 `CHAT_CONTEXT__MEMORY_CONFIG__*` 覆盖）：

| 字段 | 默认 | 说明 |
|------|-----:|------|
| `search_limit` | `5` | 搜索 `top_k` 与本地再截断上限 |
| `search_threshold` | `0.1` | 聊天检索传入 Mem0 的语义分数阈值 |

HTTP 超时（写死在 `MemoryService`，非配置项）：

| 调用 | 超时 |
|------|-----:|
| 搜索 | `5s` |
| 写入 / 列表 / 删除 | `30s` |

聊天侧行为：

- 简单应答短句（如「好的」「继续」「ok」）会跳过记忆搜索，避免噪声注入；
- 搜索结果按 `score` 降序，再按 `search_limit` 截断，映射 `relevance`（≥0.8 高 / ≥0.5 中 / 其余低）后注入 user prompt 的 `<user_memories>`；
- 命中的记忆会写入用户消息 `message_metadata.user_memories`（供 eval replay 提取）；
- `ChatRequest.memories` 非空时跳过服务端 `memory_search`，直接使用预注入结果；
- 对话结束后由后处理 fire-and-forget 写入 Mem0（user + assistant 两条）；
- Mem0 HTTP 失败只打 warning，不阻断主对话。

产品侧 v1/v2 检索语义见 `docs/mem0/`（分析文档，不等于本仓库集成契约）。

## 3. 鉴权方式

受保护接口通过依赖注入校验 JWT：

- `require_auth`：仅校验认证是否通过；
- `get_auth_token_info`：校验后提取 `user_id` 等载荷字段。

典型流程：

1. 前端调用登录接口；
2. 从响应头读取 `x-secret-token-info` 并持久化；
3. 后续请求携带 `Authorization` 头访问受保护接口；
4. 后端依赖注入完成 token 验证与用户身份提取。
