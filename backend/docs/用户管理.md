# 用户与认证模块说明（当前实现）

> 状态：现网实现。本文档以 `app/api/auth.py`、`app/api/user.py`、`app/core/jwt.py` 为准。

## 1. 认证接口（`/api/auth`）

- `POST /api/auth/sms/send`：发送短信验证码
- `POST /api/auth/sms/login`：短信验证码登录
- `POST /api/auth/wechat/init`：微信登录初始化
- `POST /api/auth/wechat/login`：微信登录回调登录
- `POST /api/auth/logout`：退出登录

说明：

- 登录成功后，服务端会在响应头写入 `x-secret-token-info`；
- 该 token 用于后续业务接口的 `Authorization: Bearer <token>` 鉴权。

## 2. 用户接口（`/api/user`）

- `GET /api/user/detail`：获取当前用户信息
- `PUT /api/user/update_info`：更新用户资料
- `GET /api/user/memories`：获取用户记忆列表
- `DELETE /api/user/memories/{memory_id}`：删除单条记忆

补充：

- 头像上传：`POST /api/avatars/upload`；读取：`GET /api/avatars/{filename}`。

## 3. Mem0 用户记忆服务

当前用户记忆由 `app/services/user/memory_service.py` 封装 Mem0 REST API。配置位于
`settings.chat_context.memory_config`：

```yaml
chat_context:
  memory_config:
    base_url: "https://mem0.example.com"
    api_key: "mem0-api-key"
    search_limit: 10
    search_threshold: 0.5
```

启用条件：

- `base_url` 与 `api_key` 均非空时才会调用 Mem0；
- 任一为空时，记忆检索返回空列表，写入/删除直接跳过；
- 请求头固定携带 `X-API-Key: <api_key>`。

聊天链路中的使用时机：

1. 回答生成前，`ChatService.search_user_memories()` 会调用 `POST /search` 检索当前用户相关记忆；
2. 回合结束后，`PostProcessService` 会后台调用 `POST /memories` 写入用户问题与助手回答；
3. `/api/user/memories` 系列接口用于用户查看或删除 Mem0 中的记忆。

Mem0 请求契约：

| 操作 | Mem0 路径 | 核心参数 |
|------|-----------|----------|
| 写入 | `POST /memories` | `messages`、顶层 `user_id`，可选 `run_id` / `metadata` |
| 搜索 | `POST /search` | `query`、`filters.user_id`、`top_k`、可选 `threshold` |
| 列表 | `GET /memories` | query 参数 `user_id` |
| 删除单条 | `DELETE /memories/{memory_id}` | path 参数 `memory_id` |

常见排障：

- 记忆始终为空：检查 `base_url`、`api_key` 是否同时配置，以及 Mem0 实例是否可达；
- 搜索结果过少：检查 `search_threshold` 是否过高，或 `search_limit` 是否过小；
- 删除接口返回 `502`：后端会透传 Mem0 删除失败，优先查看 Mem0 服务日志和 `X-API-Key` 是否有效。

## 4. 鉴权方式

受保护接口通过依赖注入校验 JWT：

- `require_auth`：仅校验认证是否通过；
- `get_auth_token_info`：校验后提取 `user_id` 等载荷字段。

典型流程：

1. 前端调用登录接口；
2. 从响应头读取 `x-secret-token-info` 并持久化；
3. 后续请求携带 `Authorization` 头访问受保护接口；
4. 后端依赖注入完成 token 验证与用户身份提取。
