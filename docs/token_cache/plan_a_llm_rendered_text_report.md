# 方案 A（llm_rendered_text 固化）缓存命中率对比报告

> 优化内容: 当轮增强后的 tool_guided_user_message（含 memories / RAG / attachment / datetime）
> 持久化到 `message_metadata.llm_rendered_text`，历史回放优先使用固化文本（fallback 裸文本）。
> 目的: 消除跨 turn 前缀断裂 —— 第 N 轮发送的 user message 在第 N+1 轮逐字复现，前缀缓存可续到对话尾。
>
> 数据源: Langfuse ClickHouse `events_full`（prod 项目 `cmpwh4pcg0002qn07mv4f20af`，模型 qwen3.8-max）
> 采集脚本: `backend/scripts/token_cache_stats.py`
> 核心指标: **跨 turn 首调 cache%** = 每个 trace（一个 chat-turn）首次 GENERATION 的
> `cached / (input + cached)`，直接度量跨 turn 前缀连续性。
> 报告时间: 2026-09-03

---

## 3. 逐轮对比（核心证据）

### Conversation 1 — 财务分析 AI Agent（旧 01a0471e… → 新 01a065bd…，6 turns）

| Turn | 旧 first% | 新 first% | 新 input | 新 cached | 判定 |
|------|-----------|-----------|----------|-----------|------|
| T1 | 0.0% (冷启动) | 89.8% | 695 | 6,144 | system prompt 热缓存命中 |
| T2 | **13.1%** | 12.1% | 44,791 | 6,144 | 见下方分析：结构性低点，非断裂 |
| T3 | 95.8% | **96.3%** | 1,969 | 50,688 | ✅ T2 的 4 万 token 整段被缓存复用 |
| T4 | 96.3% | 96.2% | 2,062 | 52,224 | ✅ |
| T5 | 84.6% | 93.3% | 3,912 | 54,272 | ✅ |
| T6 | 92.7% | 94.7% | 3,232 | 57,344 | ✅ |

T2 分析: cached=6,144 恰等于 T1 结束时的缓存前缀 → **跨 turn 前缀完全命中，未断裂**。
首调比例低是因为该轮 user message 自带约 4 万 token 新增 RAG 内容，新内容物理上无法命中缓存。
决定性证据是 T3 达到 96.3% —— 若前缀断裂，T3 不可能命中。

## 5. 结论

1. **方案 A 核心目标达成**：三个会话所有轮位 cached 均精确衔接上一轮结束值，
   跨 turn 前缀零断裂；旧基线的断裂 case（Conv3 T2 0%）修复为 81.4%。
2. **剩余低首调点是结构性的**（Conv1 T2、Conv2 T4）：单轮 user message 自带
   数万 token 新增 RAG/长文档内容，无法命中缓存，与前缀断裂无关。
   后续若要优化需从 RAG 注入量入手（top_k / chunk 截断），不属于本方案范围。
3. 无新增 cached 卡死 trace。
