# 认证流程

## 前端流程图

```mermaid
sequenceDiagram
    participant User as 用户
    participant Frontend as 前端应用
    participant Storage as 本地存储
    participant Backend as 后端API
    
    Note over Frontend,Storage: 场景1: 页面加载和认证检查
    Frontend->>Storage: 检查登录状态(读取Token)
    Storage-->>Frontend: 返回Token或null
    
    alt 未登录
        alt 当前路由为 /login
            Frontend->>User: 显示登录页面
        else 当前路由不为 /login
            Frontend->>Frontend: 跳转至 /login
            Frontend->>User: 显示登录页面
        end
    else 已登录
        alt 当前路由为 /login
            Frontend->>Frontend: 跳转至 /chat
        else 当前路由不为 /login
            Frontend->>User: 保留当前页面
        end
    end
    
    Note over User,Backend: 场景2: 登录流程
    User->>Frontend: 输入手机号和验证码
    User->>Frontend: 点击登录按钮
    Frontend->>Backend: 调用登录接口(手机号+验证码)
    
    alt 登录成功
        Backend-->>Frontend: 返回JWT Token
        Frontend->>Storage: 保存Token到localStorage
        Storage-->>Frontend: 保存成功
        Frontend->>Frontend: 跳转至 /chat
    else 登录失败
        Backend-->>Frontend: 返回错误信息
        Frontend->>User: 显示错误提示
    end
    
    Note over Frontend,Backend: 场景3: API请求流程
    Frontend->>Frontend: 发起API请求
    Frontend->>Storage: 从localStorage获取Token
    
    alt Token存在
        Storage-->>Frontend: 返回Token
        Frontend->>Frontend: 添加认证头部 Authorization Bearer token
        Frontend->>Backend: 发送请求(带Token)
    else Token不存在
        Storage-->>Frontend: 返回null
        Frontend->>Backend: 发送请求(不带Token)
    end
    
    Backend-->>Frontend: 返回响应
    
    alt 响应状态码为401
        Frontend->>Storage: 清除Token
        Storage-->>Frontend: 清除成功
        Frontend->>Frontend: 跳转至 /login
        Frontend->>User: 显示登录页面
    else 其他错误
        Frontend->>User: 处理错误
    else 成功
        Frontend->>User: 返回数据
    end
```

### 流程说明

#### 1. 页面加载时的认证检查
- **未登录状态**：
  - 如果当前在 `/login` 页面，直接显示登录页面
  - 如果不在 `/login` 页面，跳转至 `/login` 页面
  
- **已登录状态**：
  - 如果当前在 `/login` 页面，跳转回 `/chat` 页面
  - 如果不在 `/login` 页面，保留当前页面，继续正常流程

#### 2. 登录流程
- 用户在登录页面输入手机号和验证码
- 点击登录按钮后调用登录接口
- 登录成功后：
  - 保存 Token 到本地存储（localStorage 或 sessionStorage）
  - 跳转至 `/chat` 页面
- 登录失败则显示错误提示，用户可以重新输入

#### 3. 请求认证头部
- 每次发起 API 请求时，通过请求拦截器处理
- 从本地存储获取 Token
- 如果 Token 存在，在请求头中添加 `Authorization: Bearer {token}`
- 如果 Token 不存在，不添加认证头部（允许公开接口）

#### 4. 响应处理
- 通过响应拦截器检查响应状态码
- 如果返回 401（未授权），说明 Token 已过期或无效：
  - 清除本地存储的 Token
  - 跳转至 `/login` 页面重新登录
- 其他错误正常处理，成功则返回数据

## 后端流程图

```mermaid
sequenceDiagram
    participant Frontend as 前端
    participant Backend as 后端
    participant Cloudbase as Cloudbase
    participant Middleware as 认证中间件
    
    Note over Frontend,Cloudbase: 场景1: 验证码发送流程
    Frontend->>Backend: 请求发送验证码(手机号)
    Backend->>Cloudbase: 发送验证码请求
    Cloudbase->>Cloudbase: 处理验证码发送
    
    alt Cloudbase 响应成功
        Cloudbase-->>Backend: 返回成功
        Backend-->>Frontend: 返回 code:0
    else Cloudbase 响应失败
        Cloudbase-->>Backend: 返回错误信息
        Backend-->>Frontend: 返回错误信息
    end
    
    Note over Frontend,Cloudbase: 场景2: 验证码登录流程
    Frontend->>Backend: 发送登录请求(手机号+验证码)
    Backend->>Cloudbase: 验证手机号和验证码
    
    alt 验证成功
        Cloudbase->>Cloudbase: 生成 JWT Token
        Cloudbase-->>Backend: 返回 JWT Token
        Backend-->>Frontend: 返回 JWT Token
        Frontend->>Frontend: 存储 JWT 到 localStorage
        Frontend->>Frontend: 跳转到 chat 页面
    else 验证失败
        Cloudbase-->>Backend: 返回验证失败
        Backend-->>Frontend: 返回登录失败信息
    end
    
    Note over Frontend,Middleware: 场景3: 请求认证流程
    Frontend->>Backend: 请求 conversations(带JWT Token)
    Backend->>Middleware: 请求进入认证中间件
    Middleware->>Middleware: 从Header提取JWT Token
    
    alt JWT Token 不存在
        Middleware-->>Backend: 认证失败
        Backend-->>Frontend: 返回 401 未授权
    else JWT Token 存在
        Middleware->>Middleware: 验证JWT有效性(签名+过期时间)
        
        alt JWT 有效
            Middleware-->>Backend: 认证通过
            Backend->>Backend: 执行业务逻辑
            Backend-->>Frontend: 返回数据
        else JWT 无效或过期
            Middleware-->>Backend: 认证失败
            Backend-->>Frontend: 返回 401 未授权
        end
    end
```

### 流程说明

#### 1. 验证码发送流程
- 前端发起验证码发送请求
- 后端接收请求后，向 Cloudbase 发送验证码发送请求
- Cloudbase 处理完成后，后端返回 `code:0` 表示成功，或返回错误信息

#### 2. 验证码登录流程
- 前端发送手机号和验证码到后端
- 后端向 Cloudbase 验证手机号和验证码是否正确
- 如果验证失败，后端返回错误信息给前端
- 如果验证成功：
  - Cloudbase 生成 JWT 认证 Token
  - 后端将 JWT Token 返回给前端
  - 前端收到 JWT 后，存储到 `localStorage`
  - 前端自动跳转到 `/chat` 页面

#### 3. 请求认证流程
- 前端在 `/chat` 页面发起 `/conversations` 等业务请求
- 请求头中包含 `Authorization: Bearer {JWT}`
- 后端接收请求后，通过认证中间件处理：
  - 从请求头中提取 JWT Token
  - 检查 JWT 是否存在
  - 如果不存在，直接返回 401 未授权
  - 如果存在，验证 JWT 的有效性（签名、过期时间等）
  - 如果 JWT 无效或已过期，返回 401 未授权
  - 如果 JWT 有效，继续执行业务逻辑并返回数据

#### 4. 认证中间件职责
- **JWT 提取**：从 `Authorization` 请求头中提取 Bearer Token
- **JWT 验证**：验证 Token 的签名、过期时间等
- **权限控制**：根据验证结果决定是否允许访问业务接口
- **错误处理**：统一处理认证失败的情况，返回标准的 401 响应
