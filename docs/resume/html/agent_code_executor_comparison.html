🚀 Agent 代码执行器选型对比

面向 Shopee 内部 AI Agent 平台的代码执行方案评估

推荐方案：Piston 作为默认执行引擎

Piston 在安全性、开源可控性、多语言支持、资源效率和运维成本五个维度上均表现优异，
最适合作为企业级 Agent 平台的默认代码执行后端。数据科学场景可辅以 Jupyter 作为专用执行层。

Piston 选型依据（为什么选它）

1

全栈开源，企业合规零风险

MIT 协议，从 API 服务到 Isolate 沙箱全部代码开源。Shopee 作为跨境电商企业，对代码审计和供应链安全有严格要求。Piston 可完全私有化部署，无 Vendor Lock-in，无闭源黑盒。

2

多层安全隔离，适合不可信代码

Isolate 提供 Linux namespaces + chroot + 多用户 + cgroup 的组合隔离。默认禁用网络、限制进程数（256）、文件数（2048）、内存和 CPU 时间。fork 炸弹会被 SIGKILL 直接终止，适合 Agent 执行 LLM 生成的不可信代码。

3

70+ 语言，覆盖 Agent 全场景

LLM 可能生成 Python、JavaScript、Java、Go、Rust、C++ 等任意语言代码。Piston 通过 ppman install 一键安装运行时，版本精确可控。无需为每种语言单独配置环境。

4

资源轻量，高并发无压力

执行进程瞬态启动、用完即销毁，内存快速回收。无状态架构支持水平扩展，单容器即可支撑高并发。相比 Jupyter Kernel 常驻内存（500MB+），Piston 的资源效率高出 10 倍以上。

5

运维极简，单容器即服务

docker run -p 2000:2000 ghcr.io/engineer-man/piston 一行命令启动。无需维护 Nomad/Consul 集群，无需管理 Kernel 生命周期。API 纯 REST，无 WebSocket/ZMQ 协议复杂度。

6

开发体验友好，本地可测试

macOS 上 Docker Desktop 直接运行，无需 Linux VM。REST API 简单直观，返回 JSON 包含 stdout/stderr/code/memory/time，无需解析复杂的 Jupyter Msg 协议。

🎯 选型决策

默认执行引擎：Piston — 作为 Agent 平台的通用代码执行后端，覆盖 90% 的场景（商品标题优化、素材生成、网页生成、多语言脚本等）。

专用执行层：Jupyter Kernel（加固版） — 针对数据分析类 Agent（销售数据分析、用户行为可视化、A/B 测试统计），在 gVisor/Kata 容器内运行，限制并发数和资源配额，作为可选后端而非默认。

排除项：E2B — 技术先进但后端闭源，不符合 Shopee 企业合规要求；自托管运维成本过高（$1,250+/月），且 macOS 无法本地测试。
