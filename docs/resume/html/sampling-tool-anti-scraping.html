一、浏览器设备指纹伪装
1.1 动态 DeviceProfile 生成器

源码: src/shared/utils/deviceProfile.ts

每次创建浏览器上下文时，随机构造一组内部一致的设备配置，确保 UA / platform / screen / hardware 属性相互匹配。

属性生成策略
操作系统Windows 10/11 (70%)、macOS (25%)、Linux (5%)，按权重采样
Chrome 版本131-136，按真实发布分布加权（133/134 占主导）
User-Agent根据平台动态拼接，macOS 随机 6 个大版本，Windows 随机 NT 10.0/11.0，build 号随机
屏幕分辨率Mac 7 种（1440×900 ~ 2560×1440）、Windows 6 种、Linux 4 种
CPU 核数4/8/12/16 核，按真实分布加权
内存8/16/32GB，Mac 偏向 16GB，Windows/Linux 偏向 8-16GB
maxTouchPoints桌面设备统一为 0
1.2 反检测注入脚本

源码: src/infrastructure/browser/libs/anti-detection.js

通过 context.addInitScript({ path, arg: deviceProfile }) 在每个页面加载前注入，参考 undetected-chromedriver。接收 DeviceProfile 参数，所有属性从 profile 读取。

Navigator 属性覆盖

属性来源说明
navigator.webdriver固定 false最基本的自动化检测点
navigator.platformprofile.platform与 UA 一致
navigator.hardwareConcurrencyprofile.hardwareConcurrencyCPU 核数
navigator.deviceMemoryprofile.deviceMemory设备内存
navigator.plugins模拟 5 个插件对象空插件数组是自动化特征

Screen 属性覆盖

属性来源
screen.width / heightprofile.screenWidth / screenHeight
screen.availWidth / availHeight同上
screen.colorDepth / pixelDepthprofile.colorDepth（固定 24）

Chrome Runtime 模拟

构造完整 window.chrome 对象：chrome.app、chrome.runtime（含 getPlatformInfo() 根据 profile.os 动态返回）、chrome.cookies、chrome.storage.local。

检测对抗

删除 chromedriver 特征变量 删除 _webDriverEvaluated 修补 Function.prototype.toString 修补 permissions.query 强制 attachShadow open mode 清除自动化 CSS 属性 注入伪造 localStorage 原型链完整性修复

二、网络代理
2.1 住宅代理

源码: src/shared/config/playwright.config.ts → getProxyConfig()

配置项值
供应商Proxyrack 住宅代理（unmetered.residential.proxyrack.net）
端口池10036-10059，共 24 个端口
地理位置绑定username 中带 country=${region}，按任务 region 匹配目标国家
IP 刷新refreshMinutes=300，每 5 小时自动轮换 IP
2.2 重试换代理

源码: src/core/executor.ts → resolveRetryProxyPort()

首次尝试使用账号自带代理端口；第 2 次起从 proxyPortList 中随机选取不同端口，绕过单 IP 封锁。

👤
三、账号生命周期管理
3.1 账号池状态机

源码: src/infrastructure/services/redis/AccountPoolManager.ts

每个账号 4 种状态，通过 Redis Lua 脚本原子操作：

free → in_use → cooldown → free（循环）  |  expired（终态）
状态说明
free空闲可用，等待分配
in_use正在执行任务
cooldown任务完成后的冷却期，防止高频使用同一账号
expired登录态失效，需人工重新登录
3.2 冷却机制

源码: src/infrastructure/services/RedisServer.ts → setAccountCooldown()

任务完成后账号进入 cooldown，冷却时间可按 aiPlatform 配置。设置 TTL 标记，到期后自动回收到 free 池，避免同一账号短时间高频请求。

3.3 登录态持久化（storageState）

账号的 cookies + localStorage 以 Playwright storageState 格式存储在 Redis。创建上下文时注入避免重新登录；任务成功后回写 Redis 保持 cookie 活跃。账号 key 格式: email:proxyPort。

3.4 登录失效检测与告警

源码: src/core/executor.ts → initializePage()

每次打开目标平台后检查登录状态。失效时标记账号为 expired，发送 SeaTalk 告警，抛出 AccountLoginExpiredError 终止所有重试。

四、浏览器启动参数

源码: src/shared/config/playwright.config.ts → getPlaywrightConfig()

参数作用
--disable-blink-features=AutomationControlled禁用 Blink 引擎的自动化检测特征

--disable-extensions禁用扩展，减少特征
--start-maximized非 headless 时最大化窗口，模拟真实用户

六、静态资源缓存

源码: src/infrastructure/browser/managers/contextManager.ts

通过 playwright-network-cache 缓存静态资源，TTL 2 天，覆盖 JS / CSS / 图片 / 字体 / SVG。减少重复请求，降低被识别为爬虫的风险。

🔄
七、Kafka 消费层流控保护

源码: src/infrastructure/services/KafkaConsumerService.ts

机制说明
最大并发任务数MAX_CONCURRENT_TASKS = 1，同一时刻只执行一个采样任务
账号池为空暂停可用账号为 0 时暂停消费，每 5 秒轮询恢复
并发超限暂停运行中任务数 > 1 时暂停消费，任务完成后自动恢复
消息解析失败跳过JSON 解析失败或校验不通过直接提交 offset 跳过，避免死循环
🔁
八、重试策略中的反爬考量

源码: src/core/executor.ts

策略说明
默认重试 3 次DEFAULT_RETRY_COUNT = 3
单次超时 5 分钟DEFAULT_TIMEOUT_MS = 5 * 60 * 1000
重试换代理第 2 次起随机切换代理端口
账号复用整个 execute 生命周期复用同一账号，不重复取号
不重试错误AccountLoginExpiredError、NoWebSearchError 立即终止

1

Redis 原子操作，free → in_use
2

动态 DeviceProfile 生成 → 住宅代理注入 → storageState 注入 → 反检测脚本注入 → 静态资源缓存
3
页面操作
验证码/拦截页检测 → 登录状态检查 → AI 交互 + 数据采集

结果处理
成功 → storageState 回写 Redis, 账号 → cooldown ｜ 失败 → 错误分类, 重试(换代理) 或 终止
5
账号释放
in_use → cooldown, TTL 后自动 → free
