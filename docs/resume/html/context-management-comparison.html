🔧 二、单轮调用：工具返回结果过长时的处理

2.1 chat-agent — FAISS 语义截断

策略：语义相关性过滤
原理：将工具结果按 Markdown 切块 → 向量化 → 与用户 query 计算相似度 → 贪心选择 top-K 块直到 token 预算
  • 容错阈值: tolerance_tokens = 6000（低于此不压缩）
  • 目标阈值: threshold_tokens = 5000
  • chunk_size: 1000 字符, overlap 200 字符
  • Fallback: 如果没选中任何 chunk，返回第一个 chunk

特点：唯一使用 语义相关性 而非纯机械截断的框架。保留与用户问题最相关的片段，而非简单的头尾。

2.2 deer-flow — 两级策略（磁盘外部化 + 头尾截断）

Tier 1 — 磁盘外部化 (preferred):
  触发: 结果 > 12,000 chars
  操作: 完整内容写入磁盘 .tool-results/，替换为 head(2000) + 文件引用 + tail(1000)

Tier 2 — Fallback 头尾截断:
  触发: 磁盘不可用时
  操作: 截断到 30,000 chars, head(8000) + 省略标记 + tail(3000)

2.3 hermes-agent — 头尾截断 + 工具结果摘要替换

终端输出截断:
  MAX_OUTPUT_CHARS = 50,000
  head(40%) + 截断通知 + tail(60%)

压缩预处理（无 LLM）:
  • _prune_old_tool_results(): 旧工具结果替换为 1 行摘要
  • MD5 去重: 相同工具结果只保留最新
  • 工具调用参数截断: JSON 字符串值 >200 字符时压缩
  • 图片替换: 旧截图替换为 [screenshot removed to save context]

2.4 claude-code — 磁盘持久化 + 分层预算

  • 单工具预算: DEFAULT_MAX_RESULT_SIZE_CHARS = 50,000
  • 消息级预算: MAX_TOOL_RESULTS_PER_MESSAGE_CHARS = 200,000
  • Token 上限: MAX_TOOL_RESULT_TOKENS = 100,000
  • 持久化: 超阈值 → 写入 tool-results/<tool_use_id>.txt
  • Microcompact (时间触发): 超过 60 分钟无交互的工具结果清除

2.5 opencode — 磁盘外部化 + 尾部截断

特点：Shell 用尾部截断（保留最新输出），文件读取用头部截断（保留开头）。截断后完整数据持久化到磁盘，模型可通过 Grep/Read 工具重新访问。

2.6 codex (OpenAI) — 中间截断 + 分层预算

  • 截断算法: truncate_middle — 保留头部+尾部，中间替换为省略提示
  • 1.2x 容量系数: 为序列化开销留余量
  • 每工具独立预算: 不同工具可在 tools/context.rs 中定义各自的 TruncationPolicy
  • MCP 工具默认限制: Bytes(1024)

📈 三、单轮结束后：Token 统计与阈值处理

3.1 chat-agent — 统一上下文守卫（四级渐进降级）

图 2：chat-agent 四级渐进降级漏斗 — 从宽松检查到强制停止的 5 层漏斗

threshold = context_limit - min(max_output_tokens, 8192) - 13000

Step 1: 检查 total_tokens <= threshold → 通过，无需操作
Step 2: 压缩所有历史轮次的工具结果（优先 summary，否则 2000 token 头尾截断）
Step 3: 按剩余预算切分历史消息窗口（从新到旧累加整轮），窗口外 → LLM 增量摘要
Step 4: 按大小压缩当前轮次的工具结果（保护最近 2 组，旧组 head-tail 500/500 字符截断）
最终: 若仍超阈值 → stop_tools（停止工具调用，切换到最终回答）

反抖动保护：3 次连续失败 → 进入 300s 恢复窗口

3.2 deer-flow

  • 默认关闭！需手动 enabled=True
  • max_tokens = 200,000（总量 input+output）
  • warn_threshold = 0.8（80% 软警告）
  • hard_stop_threshold = 1.0（100% 硬停止）
  • diff-based 计数: 跟踪 _seen_messages 字典，只累加增量

3.3 hermes-agent

  • 字符估算: (total_chars + 3) // 4 + image_tokens
  • 阈值: effective_input_budget * 50%（最激进的触发点）
  • 三次检查点: ① 轮次序言 ② 工具结果追加后 ③ API 响应后
  • 反抖动: 2 次无效压缩后自动停止，冷却时间 60s→300s→900s 递增

3.4 claude-code

effectiveContextWindow = contextWindow - min(maxOutputTokens, 20,000)
autoCompactThreshold = effectiveContextWindow - 13,000
warningThreshold = threshold - 20,000
blockingLimit = effectiveContextWindow - 3,000
  • JSON 特殊处理: bytesPerToken=2
  • 熔断器: 3 次连续自动压缩失败后停止尝试

3.5 opencode

动态阈值：usable = input_limit - min(20K, maxOutputTokens)
200K context 模型 → 180K (90%)；128K → 108K (84%)
  • overflow 检查用 API 精确值，compaction 选择用客户端估算
  • 可配置独立 compaction agent 用不同模型

3.6 codex (OpenAI)

  • 双源 token 计数：服务端 API 精确值 + 本地字节÷4 粗估
  • 三阶段检查: ① Pre-Turn ② Mid-Turn ③ Manual
  • Token Budget 模式: 压缩时直接重置上下文窗口而非 LLM 摘要
  • 模型切换检测: comp_hash 变化或 context window 缩小时自动触发压缩

🏗️ 五、架构特色对比

🧠 chat-agent

  • 语义截断：唯一使用向量相似度筛选工具结果片段
  • 增量摘要：窗口外摘要支持增量合并
  • 四级渐进降级：统一守卫，逐级降级
  • JSON 感知参数截断：保持 JSON 合法

🦌 deer-flow

  • 中间件架构：LangChain AgentMiddleware 组合，可插拔
  • 磁盘外部化：工具结果持久化到文件
  • Skill 救援：摘要时抢救最近加载的 skill 文件
  • 默认关闭：token budget 和 summarization 默认 disabled

⚡ hermes-agent

  • 字符估算优先：不依赖 tiktoken，chars÷4 粗估
  • 三阶段压缩：无 LLM 剪枝 → 边界确定 → LLM 摘要
  • Session 分割：SQLite 物理分割，保留压缩谱系
  • 50% 阈值：最激进的压缩触发点

🎩 claude-code

  • 分层预算：单工具(50K) → 消息级(200K) → token(100K)
  • 确定性替换：ContentReplacementState 保护 prompt cache
  • Microcompact：时间触发(60min) + 缓存感知清理
  • 9 段结构化摘要：最详细的摘要模板

🔓 opencode

  • 磁盘外部化：截断后完整输出写入 TRUNCATION_DIR
  • 结构化增量摘要：5 段模板 + 旧摘要合并
  • 独立 compaction agent：可配置更便宜的模型
  • Prune 机制：独立于 compaction 的工具输出清理

🤖 codex (OpenAI)

  • 三种压缩模式可切换：本地 LLM / 远程压缩 API / Token Budget 重置
  • Pre/Mid-Turn 双阶段：工具调用循环中也能及时压缩
  • 模型切换自适应：comp_hash 变化自动触发压缩
  • AutoCompactWindow 代际追踪：支持 resume/fork

def _persist_if_too_large(self, tool_result, tool_call_id):
    if len(tool_result.content) > MAX_TOOL_RESULT_CHARS:
        path = f"/tmp/chat-agent-results/{tool_call_id}.txt"
        write_to_disk(path, tool_result.content)
        preview = tool_result.content[:PREVIEW_CHARS]
        tool_result.content = (

            f"[完整输出已保存到 {path}，共 {len(tool_result.content)} 字符，"
            f"约 {len(tool_result.content) // 4} tokens。"

        )

P0-2: per-turn 聚合预算兜底

def _enforce_turn_budget(self, tool_round_messages, context_limit):
    total_chars = sum(len(m.content) for m in tool_round_messages)
    budget = int(context_limit * 0.5)  # 工具轮最多占 50% context
    if total_chars > budget:
        sorted_msgs = sorted(tool_round_messages,
                           key=lambda m: len(m.content), reverse=True)
        for msg in sorted_msgs:
            if total_chars <= budget:
                break
            self._persist_if_too_large(msg, msg.tool_call_id)

P1-2: 时间触发工具结果清理

TOOL_RESULT_MAX_AGE_SECONDS = 3600  # 60 分钟
TOOL_RESULT_KEEP_RECENT = 5

def _cleanup_stale_tool_results(self, messages):
    tool_result_indices = [i for i, m in enumerate(messages) if m.role == "tool"]
    stale_indices = tool_result_indices[:-TOOL_RESULT_KEEP_RECENT]
    for idx in stale_indices:
        msg = messages[idx]
        age = time.time() - msg.created_at.timestamp()
        if age > TOOL_RESULT_MAX_AGE_SECONDS and len(msg.content) > 200:
            msg.content = "[工具结果已过期清除]"
            msg.summary = None
