AGENT 架构设计

ReAct vs Plan-Execute 适用场景区别

两种架构代表了智能体在决策模式上的核心分野，理解它们的区别，是设计可靠智能体系统的关键。

💡 核心理解

ReAct 是"边看边走"的即时反应，Plan-Execute 是"先谋后动"的深思熟虑。

⚙️ 核心决策逻辑对比

ReAct (Reason + Act)

核心是一个紧密的循环：思考 → 行动 → 观察 → 再思考…… 每一步行动都基于上一步的即时反馈，思考、行动和观察交织在一起，没有独立的长期规划阶段。

Plan-Execute

将过程明确分为两个解耦的阶段。计划器先根据目标生成完整或阶段性的步骤清单；执行器再严格按照计划逐步执行，并将结果返回给计划器，以便在必要时重新规划。

📊 多维度场景区别

维度 ReAct 推理-行动循环 Plan-Execute 计划-执行分离
任务确定性 低确定性，探索性强。你不知道确切的答案在哪，路径是未知的。 中/高确定性，结构化强。你知道大概需要哪些步骤，只是需要准确执行。
反馈依赖性 高度依赖即时反馈。下一步动作完全由上一步的结果决定。 阶段性反馈。主要在计划完成或遇到阻碍时，才将结果用于重新规划。
可预测性 低。行为路径不确定，难以预估全部流程。 高。整体路径在计划阶段就已可见，容易审计和干预。
容错与纠偏 自然容错。发现错误立刻在下一步纠正，非常灵活。 需显式容错。需要设计好的重规划机制，否则会在某一步卡住。
资源消耗 单次调用开销小，但总步数多。每次都要发送完整上下文（如对话历史）。 单次任务开销可能更大（生成整个计划），但执行时上下文精简，总步数可控。

🔍 场景与实例

🧠 ReAct 适用场景：复杂知识推理与动态交互

这类场景路径不确定，需要多方探索、交叉验证，就像侦探破案。

举例：用多方信源核实"2024年诺贝尔物理学奖得主是否在某大学任职"

目标：核实一个非直接陈述的事实。

  1. 思考：需要知道2024年诺奖物理学得主是谁。
  2. 行动：调用搜索引擎，搜索"2024年诺贝尔物理学奖得主"。
  3. 观察：得到结果：John Hopfield 和 Geoffrey Hinton。
  4. 思考：需要查其中一人是否在某大学任职，先查 Geoffrey Hinton。
  5. 行动：搜索"Geoffrey Hinton 多伦多大学 任职"。
  6. 观察：结果显示他是多伦多大学的荣誉教授。
  7. 思考：已找到证据可以回答，无需再查另一人。
  8. 最终答案："是的，2024年诺贝尔物理学奖得主之一 Geoffrey Hinton，在多伦多大学担任荣誉教授。"
为何不适合 Plan-Execute：无法预先规划要搜谁、搜几次，因为需要搜到谁，完全取决于第一步的结果。

其他典型场景

  • 客户服务对话：用户说"上个月买的XX坏了，但我找不到订单"，你必须先查订单，发现他没登录；引导登录后，再根据查到的具体订单，决定是退款还是换货。路径完全由用户输入动态决定。
  • 交互式代码调试：写一段代码，运行报错；根据报错信息搜索解决方案，修改代码；再次运行又出现新问题。这个"编码-测试-修复"的循环就是 ReAct 的典型应用。
📋 Plan-Execute 适用场景：多步骤、可分解的结构化任务

这类任务目标清晰，步骤可提前规划，比如做旅行攻略、写结构化的长篇报告。

举例：为你规划"深圳三日游攻略"并生成网页

目标：生成一份包含行程、交通、美食推荐的完整网页。

  1. 计划阶段：根据目标生成一个顶层计划：
    • ⬜ 步骤1：搜索"深圳三日游经典行程"
    • ⬜ 步骤2：搜索"深圳必吃美食及餐厅推荐"
    • ⬜ 步骤3：搜索"深圳地铁交通指南"
    • ⬜ 步骤4：整合以上信息，生成一个结构化的 HTML 网页
  2. 执行阶段：执行器先执行步骤1，将结果暂存。接着执行步骤2，再执行步骤3。这三步可以互不依赖，甚至能并行执行，这是 ReAct 很难做到的。最后执行步骤4，汇总所有暂存结果，生成最终答案。
为何适合 Plan-Execute：任务分解和最终产出物明确，提前规划能确保结构的完整性，并支持并行执行来提升效率。

其他典型场景

  • 批量数据处理流水线：目标是"分析这份销售表格，给出各区域总结报告"。计划是：1. 清洗数据 2. 按区域分组计算总额 3. 对每组生成分析文字 4. 汇总成 PPT。每一步都是可定义的步骤。
  • 复杂的软件部署任务：目标是"在公司内网部署一个测试应用"。计划是：1. 检查服务器资源 2. 拉取 Docker 镜像 3. 配置数据库连接 4. 启动服务 5. 验证健康检查。虽然步骤固定，但失败时需要通知计划器调整计划（如回滚或重试）。

🎯 总结：如何选择？

两个关键问题帮你做出选择

问题一：你清楚从开始到结束的每一步怎么走吗？

✅ 如果清楚 → Plan-Execute 是首选，它高效、可控、结果更确定。

❓ 如果不清楚，需要摸着石头过河 → 需要 ReAct。

问题二：任务的实时反馈和路径修正有多重要？

🔄 如果下一步行动强烈依赖上一步的具体结果 → ReAct 是必须的。

📐 如果任务可以被清晰地拆解为松耦合的子任务 → Plan-Execute 更合适。

💡 实战组合：复杂智能体系统往往会将两者结合。例如一个自动化客服 Agent，顶层用 Plan-Execute 定义"身份验证 → 理解意图 → 解决问题 → 确认满意度"的宏观流程，而在"解决问题"这一步，再调用一个 ReAct 子 Agent，去灵活地查询知识库、操作后台系统。
动手设计前，不妨先问问自己：
这个任务更像走迷宫，还是更像按食谱做菜？
这个比喻基本就能帮你做出初步选择了。
