执行流程

用户提问 │ ▼ ┌─ 软引导层 (apply_iteration_hints) ─────────────┐ │ 每轮注入动态提示 → 引导 LLM 自主判断收敛 │ │ 相似度/URL重叠 → 提示但不强制 │ └──────────────────────┬─────────────────────────┘ │ LLM 仍决定继续? ▼ ┌─ 硬约束层 (三重保险) ───────────────────────────┐ │ ① 轮次上限: MAX_TOTAL_ITERATIONS = 10 │ │ ② Token 熔断: >80% context → 强制最终回答 │ │ ③ 工具熔断: 同工具8次失败 HALT / 同参数5次 BLOCK│ └──────────────────────┬─────────────────────────┘ │ ▼ 强制最终回答（不再调用工具）

设计哲学 总结

  • 软引导命中率 ~80%+：大多数情况下 LLM 在提示下自主收敛，用户体验无缝
  • 硬约束是最后安全网：三层互不依赖，从轮次、上下文、工具错误三个维度独立兜底
  • 渐进式惩罚：warn → block → halt，给 LLM 充分的自我纠正机会
  • 成功即重置：计数器在成功时 pop 清零，不惩罚正常调用链路
面试话术: "我们采用双层治理——软引导先用动态提示让 LLM 自主收敛，硬约束兜底确保不会无限循环。三层硬约束分别从轮次、上下文、工具错误三个维度兜底，互不依赖。"
