SSE Stream Relay — 核心价值

  • • Redis Stream (XADD/XREAD) 解耦 Producer/Consumer
  • • 每个 event 带自增 id，断连后 xrange 补漏 + xread 等新
  • • Lua 脚本原子操作：append 检查状态 + stop CAS 竞争
  • • close 后 TTL 缩短至 30min，支持窗口内续传
  • • 跨 Worker 停止：meta status=stopped → Producer cancel

Turn 幂等 — SET NX 竞争锁

  • • 网络重试可能导致同一消息重复创建
  • • SET NX "pending" 抢锁 → 成功者建消息 → 写回 result
  • • 失败者 GET 轮询等待 result，超时 5s 返回 503
  • • pending TTL=60s（防死锁），result TTL=7200s
  • • 异常时主动释放 pending，避免其他请求长时间阻塞

L2 缓存 — 回退的教训

  • • 会话列表 P50=7KB，PG 查询 0.07ms（有覆盖索引）
  • • Redis GET 往返 ~0.3ms + JSON 反序列化 > 直查 PG
  • • 每次发消息失效（高频写），命中率极低
  • • 仅保留用户详情缓存（低频写、体积极小、跨接口复用）
  • • 结论：小数据 + 高频写 → 缓存收益为负
