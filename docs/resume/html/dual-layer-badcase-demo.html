🎯 效果对比

❌ 无治理

  • 工具调用 7-10+ 次
  • Token 消耗 8K-15K+
  • 响应时间 >30s
  • 大量重复信息
  • 用户可能直接关闭

✅ 有双层治理

  • 工具调用 4 次（软引导提前收敛）
  • Token 消耗 ~4K（减少 50%+）
  • 响应时间 ~12s
  • 信息去重率 >70%
  • 80% 情况软引导即收敛

🎤 面试话术

"我们的双层治理分软引导和硬约束两层。以搜索场景为例——"

  • 软引导：每轮调用工具前，根据搜索次数、URL 提取量、查询相似度等指标动态注入提示。实测 80% 的情况下 LLM 在 1-2 条提示后就会自主收敛。
  • 硬约束：如果 LLM 无视提示继续调用，三层硬约束兜底——轮次上限 10 次、上下文 Token 超 80% 强制截断、同参数失败 5 次阻断。三层互不依赖。
  • 渐进式惩罚：工具失败场景下，warn(2次) → warn+恢复建议(3次) → BLOCK(5次)，给 LLM 充分的自我纠正机会，而不是粗暴截断。
  • 效果：优化前一次对话平均 7-8 次工具调用、15K+ tokens；优化后降到 3-4 次、~4K tokens，响应时间缩短 60%。
追问预判："如果 LLM 在软引导下仍然不收敛怎么办？" → 硬约束兜底。如果 LLM 在 BLOCK 后仍尝试同参数调用，guardrail 每次都直接返回 BLOCK 消息不执行，LLM 被迫换策略或在轮次上限后强制给出最终回答。
