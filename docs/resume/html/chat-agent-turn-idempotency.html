Turn 幂等机制 — 作用流程

解决"同一请求重复发送导致重复创建消息"的问题 · SET NX 分布式锁

核心机制：SET NX 竞争锁

  • • SET NX = Set if Not eXists，原子操作
  • • 多个 Worker 同时 SET NX 同一个 key，只有一个成功
  • • 成功者（winner）负责创建消息，失败者（loser）等待
  • • loser 每 100ms GET 一次，直到拿到 winner 写回的 result
  • • 超时 5s 返回 503，前端可重试

防死锁设计

  • • pending 值 TTL = 60s，即使 winner 崩溃也能自动释放
  • • winner 的 create_fn 异常时，主动 DELETE key 释放锁
  • • loser 发现 key 消失（pending 过期），重新尝试 SET NX
  • • result 值 TTL = 7200s，足够覆盖续传窗口

前端配合

  • • 前端生成 client_turn_id (UUID)，同一发送动作共享
  • • 网络重试时自动带上同一个 id
  • • 收到 idempotent_hit 响应后，直接续传已有流
  • • 无需用户感知，透明去重
