# PDF→Markdown 技术方案评估体系

## 评估维度（7 维度，每项 1-5 分）

### 1. 速度（1-5 分）


| 分数  | 标准        |
| --- | --------- |
| 5   | 平均 < 2s   |
| 4   | 平均 2-10s  |
| 3   | 平均 10-30s |
| 2   | 平均 30-60s |
| 1   | 平均 > 60s  |


**实测数据：**


| 方案         | 总耗时    | 平均             |
| ---------- | ------ | -------------- |
| MarkItDown | 1.71s  | 0.29s → **5分** |
| MinerU     | 47.58s | 7.93s → **4分** |
| Docling    | 58.39s | 9.73s → **4分** |


---

### 2. 文本完整率（1-5 分）

> 衡量文字内容是否被完整提取，有无遗漏段落、截断、乱码。


| 分数  | 标准            |
| --- | ------------- |
| 5   | 全文无遗漏、无截断、无乱码 |
| 4   | 个别字符错误，整体完整   |
| 3   | 有少量段落遗漏或截断    |
| 2   | 大量文字丢失或乱码     |
| 1   | 几乎无法提取文字      |


**评估方法：** 对照 PDF 原文，抽查 3 个关键段落是否完整出现在 Markdown 中。

**评测用例：**

- 用例1（员工制度）：检查条款编号是否保留、长段落是否截断
- 用例3（学术论文）：检查双栏文本是否正确合并、参考文献是否完整
- 用例6（投保指引）：检查保险条款描述是否完整

**实测数据：**


| 方案         | 文本完整率 | 备注     |
| ---------- | ----- | ------ |
| MarkItDown | 4分    | 出现重复标题 |
| MinerU     | 5分    | 无重复标题  |
| Docling    | 5分    | 无重复标题  |


---

### 3. 结构保留度（1-5 分）

> 衡量标题层级、列表、段落边界是否正确还原。


| 分数  | 标准                 |
| --- | ------------------ |
| 5   | 标题层级完全正确，列表/段落边界清晰 |
| 4   | 标题层级基本正确，个别列表格式有误  |
| 3   | 部分标题丢失或层级错乱        |
| 2   | 大量结构信息丢失           |
| 1   | 输出为纯文本，无结构         |


**评估方法：** 检查 `#`/`##`/`###` 层级是否与原文一致，列表是否用 `-`/`1.` 正确标记。

**评测用例：**

- 用例1（员工制度）：多级标题 + 条款编号（一、1.、(1)）是否保留
- 用例3（学术论文）：Abstract/Introduction/Related Work 等章节标题

**实测数据：**


| 方案         | 结构保留度 | 备注                                                                                                                      |
| ---------- | ----- | ----------------------------------------------------------------------------------------------------------------------- |
| MarkItDown | 3分    | 无法识别 PDF 中的标题层级，标题被当做普通文本；对于多栏布局，无法区分不同栏的文本；识别方式是逐行识别。                                                                  |
| MinerU     | 5分    | 能区分段落排版（段落之间有空行）；能够将 pdf 中的标题层级正确转换为 markdown 标题层级。PPT 中的多栏布局能够正确识别。PPT 顶部的页眉页脚能被正确识别为标题。对于合并单元格的表格，能够正确识别并转换为 html 表格。 |
| Docling    | 4分    | 无法区分段落排版，将换行符识别为段落。对于 pdf 中的非标准格式的有序列表，转换后产生了换行符。对于多栏布局，无法区分不同栏的文本；识别方式是逐行识别。                                           |


---

### 4. 表格还原率（1-5 分）

> 衡量 Markdown 表格的列对齐、数据完整性、表头识别。


| 分数  | 标准                |
| --- | ----------------- |
| 5   | 表格列数/行数完全正确，数据无错位 |
| 4   | 基本正确，个别单元格合并/拆分有误 |
| 3   | 能识别表格但列错位或数据丢失    |
| 2   | 表格被拆成文本行，结构丢失     |
| 1   | 完全无法识别表格          |


**评估方法：** 对比 PDF 原表格，检查行数、列数、关键数据是否正确。

**评测用例：**

- 用例6（投保指引）：保险方案对比表格（序号/险种/保险责任/方案对比）
- 用例2（技术文档）：需求优先级表格

**实测观察：**

| 方案 | 表格还原率 | 备注 |
|------|------------|---------|-----------|
| MarkItDown | 3分 | 对于 ppt 中的文字表格列（由于原始格式排版问题），可能会产生多列文本标题 |
| MinerU | 5分 | 能够正确识别并转换为 html 表格。 |
| Docling | 4分 | 对于 ppt 中的合并表格，转换为 markdown 表格，效果和原始文档稍微有些差异。 |

---

### 5. 图片处理（1-5 分）

> 衡量图片是否被提取、是否有 alt text 或上下文描述。


| 分数  | 标准                             |
| --- | ------------------------------ |
| 5   | 图片提取完整，有 alt text 或 caption 描述 |
| 4   | 图片提取完整，但无 alt text             |
| 3   | 部分图片提取，有 `<!-- image -->` 占位   |
| 2   | 图片仅作为占位符，无实际内容                 |
| 1   | 图片完全丢失                         |


**评估方法：** 对比 PDF 原图数量，检查 Markdown 中 `![...]()` 或 `<img>` 数量。

**实测数据（优惠券PRD，原含 17 张图）：**


| 方案         | 图片标记数 | 方式                                          |
| ---------- | ----- | ------------------------------------------- |
| MarkItDown | 0     | ❌ 完全丢失                                      |
| MinerU     | 17    | ✅ `![](images/xxx.jpg)`。能将图片表格转为 html 表格形式。 |
| Docling    | 0     | ❌ 仅 `<!-- image -->` 占位                     |


---

### 6. 扫描件 OCR 准确率（1-5 分）

> 衡量对纯图片型 PDF（扫描件）的文字识别能力。


| 分数  | 标准              |
| --- | --------------- |
| 5   | OCR 文字完整准确，格式保留 |
| 4   | 文字基本准确，个别字符有误   |
| 3   | 能识别大部分文字，但有明显错误 |
| 2   | 仅识别少量文字         |
| 1   | 完全无法识别（输出为空）    |


**评估方法：** 对照扫描件原文，检查关键字段（公司名、日期、编号）是否正确。

**实测数据（办税进度扫描件）：**


| 方案         | 输出大小 | 识别内容                                                 |
| ---------- | ---- | ---------------------------------------------------- |
| MarkItDown | 0B   | ❌ 完全无输出                                              |
| MinerU     | 426B | ✅ 识别出"清税证明"全文+编号+日期; 能够正确识别公章下的文字；对于手写体文字和公式，能够正确识别。 |
| Docling    | 35B  | ⚠️ 仅识别出零散字符                                          |


---

## 评分汇总表


| 维度        | 权重       | MarkItDown | MinerU   | Docling  |
| --------- | -------- | ---------- | -------- | -------- |
| 1. 速度     | 11.1%    | 5          | 4        | 4        |
| 2. 文本完整率  | 27.8%    | 4          | 5        | 5        |
| 3. 结构保留度  | 16.7%    | 3          | 5        | 4        |
| 4. 表格还原率  | 22.2%    | 3          | 5        | 4        |
| 5. 图片处理   | 11.1%    | 1          | 5        | 2        |
| 6. 扫描件OCR | 11.1%    | 1          | 5        | 2        |
| **加权总分**  | **100%** | **3.06**   | **4.89** | **3.83** |
| **简单均分**  | —        | **2.83**   | **4.83** | **3.50** |


> 加权总分 = Σ(单项得分 × 权重)，权重合计 100%，结果即为 5 分制综合得分。

**排名：** MinerU (4.89) > Docling (3.83) > MarkItDown (3.06)

**权重说明：**

- 各维度按原比例（10:25:15:20:10:10）缩放至合计 100%
- 文本完整率(27.8%) + 表格还原率(22.2%) 权重最高，因为直接影响 RAG 检索质量
- 图片处理 + 扫描件OCR 各 11.1%，仅在特定场景影响
- 速度 11.1%，因为 SaaS 调用都在秒级，差异不大

### 推荐方案：MinerU

**综合得分 4.89，六维中五项满分（5/5），是唯一在质量维度全面领先的方案。**

#### 1. 高权重维度全部拉满，直接决定 RAG 效果

文本完整率（27.8%）和表格还原率（22.2%）合计占 **50%** 权重，是检索质量的核心。MinerU 在这两项均为满分：文字无遗漏、无重复标题；表格可正确识别合并单元格并输出 HTML 表格。相比之下，MarkItDown 两项仅 3–4 分，Docling 表格还原为 4 分——在权重最高的维度上，MinerU 优势最明显。

#### 2. 结构保留度最佳，有利于分块与检索

MinerU 能正确还原标题层级（`#`/`##`/`###`）、段落边界（段间空行）、多栏排版和 PPT 页眉页脚，输出可直接用于 Markdown 分块策略。MarkItDown 和 Docling 均采用逐行识别，多栏布局易混栏、标题易被当作正文，结构分分别为 3 分和 4 分，分块后噪声更高。

#### 3. 图片与扫描件能力不可替代

实测优惠券 PRD（17 张图）：MinerU 全部提取为 `![](images/xxx.jpg)`，MarkItDown 完全丢失，Docling 仅 `<!-- image -->` 占位。办税进度扫描件：MinerU 完整识别清税证明全文、编号、日期及公章文字，MarkItDown 零输出，Docling 仅零散字符。对于含配图的产品文档和扫描件类 PDF，只有 MinerU 能覆盖。

#### 4. 速度可接受，不构成否决因素

MinerU 平均耗时 7.93s（4 分），与 Docling（9.73s）同级，慢于 MarkItDown（0.29s）。但速度权重仅 11.1%，且三者均在 SaaS 可接受的秒级范围内；以约 8 秒换取结构、表格、图片、OCR 的全面质量提升，性价比合理。

#### 5. 与备选方案的取舍


| 对比                      | 结论                                                            |
| ----------------------- | ------------------------------------------------------------- |
| vs Docling (+1.06 分)    | 文本完整率持平，但结构、表格、图片、OCR 全面领先；Docling 更适合对速度不敏感、且文档不含图/扫描件的纯文本场景 |
| vs MarkItDown (+1.83 分) | MarkItDown 速度最快，但无图片提取、无 OCR、结构识别弱；仅适合简单、纯文本、无扫描需求的轻量场景       |


**结论：** 面向 PDF→Markdown→RAG 的主路径，MinerU 在权重最高的文本与表格维度满分，并在结构、图片、OCR 上补齐了另外两家的短板，综合性价比最高，建议作为默认解析方案。
