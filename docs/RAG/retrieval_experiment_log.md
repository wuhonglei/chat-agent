## 关键发现



### 1. 泰康养老文档是主要短板

该文档 74 个 chunks（最多），大量 HTML 表格导致：

- 同一信息（如"等待期30天"）分散在多个 chunk 中
- vector search 返回语义相似但不含 source_snippet 的 chunk
- 含 source_snippet 的 ref chunk 被排到 top-k 之外

验证案例（L1-泰康养老-T06）：

- FAISS top-5 分数范围：0.48 ~ 0.54
- ref chunk 排名第 6，分数 0.63
- 提高到 top_k=8 后该样本 recall 从 0 提升到 1.0



### 2. Recall 偏低是检索排名问题，非匹配逻辑问题

- 42 条 recall < 1 的样本中，ref chunk 全部存在于 FAISS 索引中
- 根因：ref chunk 被语义更近但不含答案的 chunk 挤出 top-k
- 提高 top_k 是直接有效的解决方式



### 3. MRR 基本不变

top_k 增大不影响 MRR（+0.0011），说明 top-1 结果已经很好，改善的是边界附近的召回。

### 4. 跨文档检索仍需专项优化

3 篇以上的跨文档问题 recall 仍为 0，仅靠提高 top_k 无法解决，需要：

- 多路召回（先按文档检索再合并）
- 或 query decomposition（将跨文档问题拆分为子问题）

### 分析

- **整体回退**：Recall 从 0.97 下降到 0.93，MRR 从 0.93 下降到 0.88

- **结论：MarkdownTextSplitter 单级分块仍是当前最优方案**
