## 2. 参数变更效果验证

### 2.1 queries 描述变更

**变更**: `"推荐使用 2-3 个查询"` → `"简单问题使用 1 个 query，复杂/多角度问题使用 2-3 个查询"`

| 指标 | 优化前 | 优化后 |
|------|-------|-------|
| avg queries/call | 2.8 | 2.3 |
| 1 query 占比 | — | 21% |
| 2 queries 占比 | — | 37% |
| 3 queries 占比 | — | 32% |
| 4 queries 占比 | — | 11% |

> 效果：有效，但 LLM 仍倾向使用 2-3 个 query。1 query 仅占 21%，还有提升空间。

### 2.2 result_per_query 默认值变更

**变更**: `10` → `5`（每个 query 的返回结果数，非总数）

| 指标 | 数值 |
|------|------|
| 显式传递 result_per_query 的比例 | 62% (39/63) |
| 传递 result_per_query=5 的比例 | 90% (35/39) |
| 传递 result_per_query=8 的比例 | 5% (2/39) |
| 未显式传递（使用默认值 5） | 38% (24/63) |

> 效果：生效。LLM 大部分时候显式传递了 `result_per_query=5`。

**实际搜索结果数验证：**

- 理论最大：avg 2.3 queries × result_per_query 5 = 11.5 results
- 实际返回：avg 8.7 results（部分 query 返回不足 5 条，符合预期）
- 对比优化前：avg 2.8 queries × result_per_query 10 = 28 → 实际 avg ~10 results

### 2.3 chunks_per_source 默认值变更

**变更**: `3` → `2`（每个搜索结果的摘录段数）

| 指标 | 优化前 | 优化后 |
|------|-------|-------|
| 每结果摘录段数 | 3 | 2 |
| 每次搜索返回结果数 | avg 10 | avg 8.7 |
| Tool result 总字符数 | 43K-88K | avg 13,886 |

> 效果：生效。总字符数下降 ~70%。
