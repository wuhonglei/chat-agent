## 2. 参数变更效果验证

### 2.1 queries 描述变更

**变更**: `"推荐使用 2-3 个查询"` → `"简单问题使用 1 个 query，复杂/多角度问题使用 2-3 个查询"`

| 指标 | 优化前 | 优化后 |
|------|-------|-------|
| avg queries/call | 2.8 | 2.3 |
| 1 query 占比 | — | 21% |
| 2 queries 占比 | — | 37% |
| 3 queries 占比 | — | 32% |
| 4 queries 占比 | — | 11% |

> 效果：有效，但 LLM 仍倾向使用 2-3 个 query。1 query 仅占 21%，还有提升空间。

### 2.2 result_per_query 默认值变更

**变更**: `10` → `5`（每个 query 的返回结果数，非总数）

| 指标 | 数值 |
|------|------|
| 显式传递 result_per_query 的比例 | 62% (39/63) |
| 传递 result_per_query=5 的比例 | 90% (35/39) |
| 传递 result_per_query=8 的比例 | 5% (2/39) |
| 未显式传递（使用默认值 5） | 38% (24/63) |

> 效果：生效。LLM 大部分时候显式传递了 `result_per_query=5`。

**实际搜索结果数验证：**

- 理论最大：avg 2.3 queries × result_per_query 5 = 11.5 results
- 实际返回：avg 8.7 results（部分 query 返回不足 5 条，符合预期）
- 对比优化前：avg 2.8 queries × result_per_query 10 = 28 → 实际 avg ~10 results

### 2.3 chunks_per_source 默认值变更

**变更**: `3` → `2`（每个搜索结果的摘录段数）

| 指标 | 优化前 | 优化后 |
|------|-------|-------|
| 每结果摘录段数 | 3 | 2 |
| 每次搜索返回结果数 | avg 10 | avg 8.7 |
| Tool result 总字符数 | 43K-88K | avg 13,886 |

> 效果：生效。总字符数下降 ~70%。

## 6. Input Token 缓存命中率对比

> 数据来源: Langfuse Prod 项目 (ai-chat-prod)
> 分析时间: 2026-06-22

### 6.1 整体对比

| 指标 | 优化前 | 优化后 | 变化 |
|------|--------|--------|------|
| GENERATION 数（主聊天模型） | 197 次 | 190 次 | -3.6% |
| 总 input tokens | 1,923,734 | 1,339,270 | **-30.4%** |
| 总 cached tokens | 661,632 | 719,360 | +8.7% |
| **缓存命中率** | **34.39%** | **53.71%** | **+19.32 pp** |

### 6.2 按模型细分

**优化前：**

| 模型 | 调用次数 | Input Tokens | Cached Tokens | 缓存命中率 |
|------|----------|-------------|---------------|-----------|
| deepseek-v4-flash | 192 | 1,891,049 | 648,192 | 34.28% |
| deepseek-v4-pro | 5 | 32,685 | 13,440 | 41.12% |
| qwen3.5-flash | 110 | 26,958 | 0 | 0.00%（title 生成） |

**优化后：**

| 模型 | 调用次数 | Input Tokens | Cached Tokens | 缓存命中率 |
|------|----------|-------------|---------------|-----------|
| deepseek-v4-pro | 190 | 1,339,270 | 719,360 | **53.71%** |
| qwen3.5-flash | 107 | 26,052 | 0 | 0.00%（title 生成） |
| deepseek-v4-flash | 0 | — | — | 不再使用 |

### 6.3 关键发现

1. **模型切换**: 优化将主聊天模型从 `deepseek-v4-flash` 切换到了 `deepseek-v4-pro`，完全停用了 `deepseek-v4-flash`。

2. **缓存命中率显著提升**: 从 34.39% 提升到 53.71%，提升了 19.32 个百分点（相对提升 56.2%）。

3. **Token 消耗降低**: 优化后总 input tokens 从 1,923,734 降至 1,339,270（减少 30.4%），与第 3 节的 token 消耗下降一致。

4. **同模型直接对比**: `deepseek-v4-pro` 在优化前仅 5 次样本（41.12%），优化后 190 次（53.71%），样本量差异大，但趋势一致。

### 6.4 结论

缓存命中率从 ~34% 提升到 ~54%，主要收益来自：

- **a)** 切换到 `deepseek-v4-pro` 模型，该模型的 prompt cache 机制更高效
- **b)** Token 消耗降低 30%，减少了重复传输的无效 token，间接提升了缓存命中比例
